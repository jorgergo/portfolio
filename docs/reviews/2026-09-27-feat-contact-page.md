## Minor

### 🟡 The channel order is a spec invariant that nothing enforces, `src/lib/site-meta.ts:119`
**Problem**: The order "email, then profiles in `cv.json` order" lives twice: in `formatContactRows` (`src/lib/cv-format.ts:283`) for the rows and in `formatChannelList` (`src/lib/site-meta.ts:119`) for the description. Spec 0011's Key invariants section says a change to the order "touches both helpers and both test files", but no test feeds one fixture to both and checks they agree. Each helper's own tests pass with either order.
**Why it matters**: If someone reorders one to match the home page (profiles first, email last, as `index.astro` draws it today), the description names channels in an order the page does not show, and every gate stays green. It is cosmetic, but it is exactly the drift the spec asks you to prevent.
**Suggested fix**: Add one Vitest case that passes the same `basics` fixture to both helpers and asserts that the names in `formatChannelList`'s output, lowercased, equal the keys of `formatContactRows` in order. Alternatively, carry `network` on `ContactRow` and build the description's list from the rows, so there is one order to change.

### 🟡 The cap's layout promise is proven by hand only, `src/lib/cv-schema.ts:40`
**Problem**: `CV_LIMITS.email` is 27 because "Plex Mono is 10px per glyph in CI, so 27 characters is the most that fits" the 272px phone column (the comment at lines 14 to 17). The arithmetic is right today (270px against 272px, with `px-6` in `BaseLayout.astro:78` and the 16px base size), and Vitest proves 27 passes and 28 fails. What no durable test proves is that 27 glyphs of the real rendered font fit the real rendered column. The 320px test at `e2e/site.spec.ts:2524` runs on today's 19 character address, and the 27 character case is one ticked hand step in `verify.md`.
**Why it matters**: The cap and the column are two numbers in two files with no test between them. A change to the shell padding, the base font size, or the `NavRow` label rule (`shrink-0`) leaves 27 wrong, and the first sign is an address that runs off a phone screen after a content edit.
**Suggested fix**: In the 320px test you already measure the value span and the row. Add one assertion that ties the cap to those measurements: `CV_LIMITS.email` times the measured glyph width (`value.width / basics.email.length`) is at most the row's width. It costs one line, needs no fixture, and fails the moment the column, the font, or the cap moves out of step.

### 🟡 The scope says verified while two manual steps stay open, `docs/scope/scope.md:170`
**Problem**: `docs/scope/scope.md:170` ticks "Verify it" for the contact page, but `docs/specs/0011-contact-page/verify.md:12` (click the email row, the mail app opens) and `:13` (VoiceOver reads the three links) are still unticked. The VoiceOver step is the only check of the known Safari cost the spec records (the list role is dropped outside a `<nav>`), and no page test can cover it.
**Why it matters**: The scope is what the next `/scope` and `/sync` runs read. A ticked row with open steps behind it hides the one accessibility check that still needs a person, and the same gap was flagged on the projects page review.
**Suggested fix**: Run the two steps on a Mac and tick them, or leave "Verify it" open in the scope with a note naming the two steps, as the review of `feat/projects-page` asked.

- Every page expectation is derived: the Tab stops, the accessible names, the hrefs, the arrow count (filtered on the href), and the row count all come from `formatContactRows(basics)`, and the `verify.md` break steps (delete `profiles`, swap their order, change the address) prove the tests hold with no edit.

- `formatChannelList` uses `Intl.ListFormat` with `disjunction`, so removing or adding a network rewrites the description with no code edit, and `MetaCv` takes only `network`, so the tests stay plain objects.
- The deploy gate is extended in every place the `AGENTS.md` rule names: `check_page /contact`, the `/og/contact.png` fetch, `SMOKE_FILES`, and the five hand written path loops, and the smoke tests prove a one byte change or an immutable cache on `/contact` rolls the Worker back.
- The measured `fits` width in the 320px test handles the Mac (9.6px) and Linux (10px) glyph widths and skips the wrap branch for an address that already fits, so it holds for any valid content.
