## Minor

### 🟡 The scope says verified while the VoiceOver step is still open, `docs/specs/0010-projects-page/verify.md:11`
**Problem**: The uncommitted `verify.md` edit ticks every step but one: the Safari VoiceOver read (line 11), which is the only check of how a real screen reader speaks the `code for <name>` and `private code` names built from `sr-only` spans, and of the level 2 heading walk. `docs/scope/scope.md:204` already ticks `Verify it`, and spec 0010's status is still `In Progress` (`index.md:4`) while its whole build plan is ticked. The Known gaps line (verify.md:42) is honest about the list announcement, so nothing false is claimed there, but the scope and the verify file disagree.
**Why it matters**: The `sr-only` naming is the one accessibility choice on this page that Playwright can only approximate: `toHaveAccessibleName` proves what Chromium computes, not what VoiceOver says, and Safari is already the browser where this site's lists lose their role. The risk is low, since `SkipLink` uses the same `sr-only` class and the pattern is standard, but the record should say what was and was not done.
**Suggested fix**: Run the VoiceOver step and tick it, then commit the `verify.md` edit with the rest of the branch. If you would rather ship without it, untick `Verify it` in the scope or add a Known gaps line that names the open step, and set the spec's status when you decide.

### 🟡 The pair rule is a second copy of `CvEntry`'s string, `src/pages/projects.astro:21`
**Problem**: The 70 character class string that makes the name and meta share a baseline from 480px and stack below it lives twice now: `src/components/CvEntry.astro:44` and `src/pages/projects.astro:21`. The spec, `design.md:107`, and the page comment all call it "the `CvEntry` pair rule", so the intent is one rule; the code has two literals that nothing ties together. Each page's test checks its own pair at 1280px and 320px, so if one copy changes (a new breakpoint, a different gap) both suites still pass and the two pages quietly stop matching.
**Why it matters**: The site's whole design system argument is that a rule is written once and composed. This is the first place a layout rule is copied between a component and a page rather than shared, and the next page with a pair (contact, a project detail) will copy it again.
**Suggested fix**: Export the string once, for example a `PAIR` constant in a small `src/lib/` module that both `CvEntry.astro` and `projects.astro` import (Tailwind v4 scans `.ts` sources, so the classes still compile), and point the comments at it. If you prefer to keep page markup free of shared layout constants, at least say in `CvEntry.astro` that `projects.astro` carries a copy, so a change there finds both.
