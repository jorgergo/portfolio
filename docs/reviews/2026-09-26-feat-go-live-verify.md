## Minor

### 🟡 A deploy that fails after the new version is live is neither smoke checked nor rolled back, `.github/workflows/ci.yml:81`
**Problem**: `rollback` runs only when `steps.pages.outcome == 'failure'`. `wrangler deploy` uploads the assets, creates the version and its deployment, and only then configures the triggers and prints its summary. If the step exits non zero after the deployment exists (a trigger call errors, the runner loses network late), `pages` is skipped, `rollback` sees `skipped` and stays skipped, and the job goes red with an untested version live. The spec's state table says `deploy failed (stop; unchanged)`, which is not always true.
**Why it matters**: Rare, and the job is red, so you will look. But the red run reads as "nothing changed", and the README promises that a bad deploy rolls itself back. The narrow condition is right for the common case: a deploy that fails before creating a deployment must not roll the good version back to an older one, so do not widen it blindly.
**Suggested fix**: Either record the gap (the spec's state table and the README: when `deploy` itself is red, check the Deployments tab), or add a small step after a failed `deploy` that reads the live deployment's message (`wrangler deployments list`) and runs the smoke check and rollback only when that message equals `$GITHUB_SHA`.

### 🟡 The header match ignores case in the value too, against the contract and the page test helper, `.github/scripts/smoke.sh:118`
**Problem**: `grep -i -x -F` applies `-i` to the whole line, so `Cache-Control: PUBLIC, MAX-AGE=31536000, IMMUTABLE` would pass. The spec's Smoke check contract says "the name in any case and the value exactly", and `missingHeaders` in `e2e/helpers.ts:105` does exactly that (name lowered, value compared as is). So the script and the test apply two different rules while their comments say they match headers the same way.
**Why it matters**: Today's values are case insensitive tokens by their own specs, so nothing wrong ships. But the script is the gate that decides a rollback, and the rule it applies is not the one written down. The next person who tightens or loosens a header will trust the contract.
**Suggested fix**: Match the name ignoring case, then compare the value exactly in the shell (grep the `^name:` lines, `trim` the part after the first colon, compare with `=`). Or, if the looser rule is what you want, change the contract sentence and `missingHeaders` to match, so all three agree.

### 🟡 `redirects` mode has no automated test of its pass path or its Location check, `.github/scripts/smoke.sh:165`
**Problem**: The only test for `redirects` (`e2e/site.spec.ts:1103`) points it at a closed port and asserts the first status failure. The `location:` comparison on line 165, the second probe on line 170, and the `every check passed` line for this mode run only against the live zone (`verify.md`). The script hard codes `https://www.` and `http://`, so a local server cannot stand in.
**Why it matters**: This is branching logic in the script that decides whether a deploy job is red. It was checked live once, and a future edit to the probe path or the expected Location can only be caught by the next deploy. It is not a Major because a wrong answer here is a red job with no rollback, and the live check in `verify.md` did pass.
**Suggested fix**: Give the script a small test seam, for example an env var that overrides the two probe URLs (used only by tests), then drive a tiny local server that answers 301 with a right and a wrong Location, in the style of `withTamperingProxy`. If you would rather keep the script free of test hooks, add a comment by the test saying the pass path is live only, so the gap is deliberate.

## Nits
- ⚪ `.github/workflows/ci.yml:51`: `deploy` has no `timeout-minutes`. The worst case for `pages` is ten attempts of five requests at 20 seconds each plus nine pauses, about 19 minutes, and a hung wrangler call waits for GitHub's six hour default while the `production` group queues later runs behind it. `timeout-minutes: 30` is cheap insurance.
- ⚪ `e2e/helpers.ts:81`: `headerBlocks` and the `block` function in `smoke.sh` read `_headers` slightly differently. Bash resets the block on an unindented line that does not start with `/` and strips `\r`; the TypeScript version does neither, and a header line with no colon gives it a name missing its last character. Today's file has only two `/` blocks, so both agree. Either align them or soften the "reads the file the same way" comments in both files.
- ⚪ `docs/specs/0007-go-live/index.md:23` and `:24`: AC-6 and AC-7 pin `upload-artifact@v5` and `download-artifact@v6`; the workflow uses `@v7` and `@v8`, the current majors, as the spec's own "confirm the current major at build time" note allowed. Update the two ACs so the spec matches the code.
- ⚪ `docs/specs/0007-go-live/rationale.md:84`: says the rollback prompt "defaults to no". In wrangler 4.137 the confirm has `defaultValue: true`, and with no terminal attached wrangler takes the default. `--yes` is still right as belt and braces; only the sentence is wrong.
- ⚪ `e2e/helpers.ts:355`: the proxy's error handler calls `writeHead(502)` even when headers were already sent, which throws inside the handler. Test only code, and no test hits it; a guard on `outgoing.headersSent` keeps a proxy failure readable.
- ⚪ `AGENTS.md`: the Tooling section still says "Not in CI yet" for the page tests and "Deploying belongs to the Go live spec". The spec's Consequences already hand this to `/sync`; run it soon after merge so the next review does not flag the pipeline as undocumented.

## Strengths
- Secret handling is tight: `permissions: contents: read`, the token and account id only in the two steps that call wrangler, `environment: production` on top of the push to `main` `if`, and no `${{ }}` expression inside any `run:` line (`$GITHUB_SHA` comes from the environment, so nothing is interpolated into the shell).
- The rollback path is correct. `rollback` runs only when `pages` failed, `redirects` is skipped after a failure, a green `rollback` cannot turn the job green, and wrangler 4.137's `fetchDefaultRollbackVersionId` drops the current deployment before picking the previous 100% version, so a rollback after an earlier rollback still lands on the last good bytes.
- `smoke.sh` is careful shell: `set -euo pipefail` with every check inside a function called under `while !`, curl failures caught with `|| true` and read as `000`, `\r` stripped from the header dump, a `trap` for the temp dir, and it runs on bash 3.2. `bash -n` passes, and the usage, canonical, and `_headers` errors exit 1 before any request goes out.
- Every expectation is derived from `dist/` and `_headers`, so a content or header edit needs no script or test edit, in line with spec 0005 AC-16 and spec 0006 AC-18.
- The page tests are well built: `sleep` is stubbed through `PATH` so ten failed attempts take half a second, a proxy tampers one response at a time to reach the branches a healthy server cannot, and each failure case asserts the exact first line the script prints, so a message change is caught too.
- The fixed viewport assumption in the email row test was replaced with a measured width, which removes the Mac versus Linux glyph rounding flake before CI ever saw it.
